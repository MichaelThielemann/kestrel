# examples/minimal

The reference instance: one `kestrel.config.ts` that activates every shipped module and one
pipeline file per flow. `docs/api.md` describes exactly this instance, and the generated sections
of the package READMEs quote its pipelines. It is a reference, not a starter — a first project
needs a handful of modules, not all of them; `docs/getting-started.md` builds that from scratch.

```
pnpm install
pnpm start          # from the repository root: boots this instance on http://127.0.0.1:4000
curl http://127.0.0.1:4000/health
```

State lands under `data/`: `data/kestrel.db` (SQLite) and `data/blobs/` (uploads, rendered pages,
`redirects.json`, `llms.txt`). Delete the folder to start over.

```
kestrel.config.ts   modules with their config, and one trigger per route, event and cron
modules.ts          the module list, bound to the step catalogue so a typo in a pipeline is a tsc error
pipelines/          one file per flow, each a name plus a list of step strings
migrations/         content migrations for migrations-default
schemas/            JSON Schemas that validate-jsonschema checks payload fields against
manifest.json       generated by `pnpm docs:generate`; do not edit
openapi.json        generated by `pnpm --filter kestrel-example-minimal openapi`; do not edit
```

Authentication is `authn-multi` with a bootstrap user `admin` in the `admin` role. The config
carries a scrypt hash, not a password; replace it with your own before using the instance:

```
node -e "import('@michaelthielemann/kestrel-authn-multi/impl').then(m => console.log(m.hashPassword(process.argv[1])))" -- <password>
```

Anonymous callers may read (`pages.read`, `settings.read`, `media.read`); everything else needs a
token from `POST /login`. The renderer is `renderer-plain` and the blob store is the local
filesystem, so static delivery works without any external service.
